# 모바일 작업 패널 탭 전환 설계

작성일: 2026-04-15

## 목표

- 모바일에서 작업 패널 전환을 아코디언보다 더 빠르게 만든다.
- `북마크`, `폴더`, `태그` 3개 작업 영역을 상단 탭에서 명확히 전환할 수 있게 한다.
- 현재 폼 상태와 기존 작업 로직은 유지한다.

## 접근 방식

### 옵션 1. 상단 세그먼트 탭형

- 모바일 작업 패널 상단에 3개 탭을 두고 선택된 패널만 본문을 보여준다.
- 현재 `mobileSidebarPanel` 상태를 그대로 재사용할 수 있다.
- 이번 슬라이스 추천안이다.

### 옵션 2. 하단 고정 작업 바

- 모바일 하단에 3개 전환 버튼을 두고 본문만 바꾼다.
- 터치 접근성은 좋지만 검색/상세/목록 흐름과 충돌 가능성이 있다.

### 옵션 3. 아코디언 유지 + 빠른 전환 칩

- 기존 아코디언을 유지하면서 상단에 작은 전환 칩만 둔다.
- 구현은 안전하지만 현재 작업 영역이 탭형만큼 분명하지 않다.

## 추천안

- 옵션 1로 진행한다.
- 모바일에서는 아코디언 대신 세그먼트 탭을 사용한다.
- 데스크톱은 기존 카드 구조를 그대로 유지한다.

## 구조

### 1. 탭 헤더

- 모바일 사이드바 상단에 `북마크`, `폴더`, `태그` 탭을 둔다.
- 각 탭은 제목과 짧은 상태 요약을 함께 보여준다.

상태 요약:

- 북마크: `새 북마크`, `작성 중`, `수정 중`
- 폴더: `N개`, 또는 `수정 중`
- 태그: `N개`, 또는 `수정 중`

### 2. 본문 전환

- 모바일에서 선택된 탭 하나만 본문을 렌더링한다.
- 탭 전환 시 폼 상태는 그대로 유지한다.
- 본문 컨테이너의 `aria-label`은 기존 `bookmark-form`, `folder-manager`, `tag-manager`를 유지한다.

### 3. 접근성

- 탭 헤더 컨테이너는 `role="tablist"`
- 각 탭 버튼은 `role="tab"`, `aria-selected`, `aria-controls` 사용
- 본문은 해당 탭과 연결된 `id`를 가진다

## 제외 범위

- 데스크톱 사이드바 구조 변경 없음
- 패널 내부 폼 배치 변경 없음
- 저장/수정/검색 로직 변경 없음

## 테스트 기준

- 모바일에서 `tablist`와 3개 탭이 보인다.
- 기본 선택 탭은 `북마크`
- `폴더` 탭을 누르면 `folder-manager` 본문이 보이고 `bookmark-form`은 숨겨진다.
- 탭에 상태 요약이 보인다.
