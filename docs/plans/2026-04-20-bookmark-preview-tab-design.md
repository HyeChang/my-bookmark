# 북마크 미리보기 탭 설계

## 목표

북마크 상세보기에서 저장된 관리 정보와 웹 크롤링 기반 미리보기를 분리한다. 사용자가 `미리보기` 탭을 열 때마다 해당 북마크 URL의 최신 웹페이지를 크롤링해 표시하되, 기존 자동 추출 저장 동작은 유지한다.

## 범위

- 상세 패널에 `상세` / `미리보기` 탭을 추가한다.
- `상세` 탭에는 사용자 입력값, 이미지, 메타 정보, 기존 액션을 유지한다.
- 기존 상세 화면의 `자동 추출` 블록은 `미리보기` 탭으로 이동한다.
- `미리보기` 탭을 열 때마다 최신 크롤링 결과를 요청한다.
- 최신 크롤링 결과는 화면 표시용이며 DB에 저장하지 않는다.
- 기존 `자동 추출 다시 시도` 메뉴는 저장된 자동 추출값을 갱신하는 현재 동작을 유지한다.

## 접근

### 1. API

새 상세 미리보기 API를 추가한다. 인증된 사용자의 북마크인지 확인한 뒤 저장된 URL을 기존 `BookmarkExtractor`로 즉시 크롤링하고 `BookmarkExtractPreview` 형태로 반환한다. 이 경로는 repository `update`를 호출하지 않는다.

### 2. 웹 클라이언트

`apps/web/src/lib/bookmarks.ts`에 상세 미리보기 로더를 추가한다. 기존 자동 추출 API와 같은 에러 매핑을 쓰되, 메시지는 상세 미리보기 상황에 맞춘다.

### 3. 상세 패널 UI

상세 패널 내부에 탭 리스트를 둔다. 기본 탭은 `상세`이며, `미리보기` 탭을 누를 때마다 미리보기 요청을 새로 보낸다. 요청 중에는 로딩 문구를 표시하고, 실패하면 오류 문구와 저장된 자동 추출값을 같은 탭 안에 보여준다. 성공하면 최신 크롤링 결과를 먼저 보여주고, 저장된 자동 추출값도 구분해서 확인할 수 있게 한다.

### 4. 상태 관리

선택된 북마크가 바뀌거나 상세 패널을 닫으면 미리보기 탭 상태와 요청 상태를 초기화한다. 탭을 다시 열면 항상 새 요청을 시작한다. 늦게 도착한 이전 요청은 request id로 무시한다.

## 비범위

- 크롤링 품질 개선
- 미리보기 결과 저장
- 별도 웹 아카이브 저장
- iframe 기반 원문 렌더링
- 상세 패널 외 북마크 카드 레이아웃 변경

## 검증

- API는 상세 미리보기 요청마다 extractor를 호출하고 DB를 갱신하지 않는다.
- 웹 UI는 상세 탭에서 자동 추출 블록을 노출하지 않는다.
- 웹 UI는 미리보기 탭에서 저장된 자동 추출값을 보여준다.
- 미리보기 탭을 열 때마다 최신 크롤링 API를 다시 호출한다.
- 크롤링 실패 시 상세 패널은 유지되고 오류가 탭 안에 표시된다.
