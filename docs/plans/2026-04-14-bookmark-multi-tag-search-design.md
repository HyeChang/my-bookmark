# 북마크 다중 태그 검색 설계

## 목표

- 북마크 검색에서 태그 필터를 단일 선택에서 다중 선택으로 확장한다.
- 여러 태그를 고르면 `AND` 조건으로 동작해야 한다.
- 기존 검색어, 검색 모드, 정렬, 기간 필터, 기타 필터와 함께 조합 가능해야 한다.

## 접근 방식

### 옵션 1: 다중 태그 OR 검색

- 선택한 태그 중 하나라도 포함하면 결과에 포함한다.
- 장점: 결과가 더 많이 나온다.
- 단점: 사용자가 여러 태그로 좁혀보는 요구와 맞지 않는다.

### 옵션 2: 다중 태그 AND 검색

- 선택한 모든 태그를 가진 북마크만 결과에 포함한다.
- 장점: 검색이 더 정밀하고, 현재 북마크 정리 용도와 잘 맞는다.
- 단점: 결과가 적게 나올 수 있다.

### 옵션 3: 태그 검색 전용 고급 문법

- 검색어 안에서 `tag:research tag:video` 같은 문법을 지원한다.
- 장점: 유연하다.
- 단점: 현재 UI와 학습 비용 기준으로 과하다.

## 추천안

- `옵션 2: 다중 태그 AND 검색`으로 간다.
- UI는 다중 선택이 잘 드러나는 체크박스 목록으로 바꾼다.
- API는 기존 `tagId` 단일 파라미터를 반복 쿼리 파라미터 형태로 확장한다.
  - 예: `?tagId=tag-1&tagId=tag-2`

## API 설계

- 대상: `GET /api/bookmarks`
- 태그 필터 입력:
  - `tagId=tag-1&tagId=tag-2`
- 라우트에서는 반복된 `tagId`를 모두 읽어 배열로 정규화한다.
- 저장소 필터는 `tagIds?: string[]`로 받아서 모든 태그가 포함되는지 검사한다.
- 태그가 하나면 기존 단일 태그 필터와 동일하게 동작한다.

## UI 설계

- 검색 폼의 `필터 태그` 단일 셀렉트를 제거한다.
- 대신 `필터 태그` 체크박스 목록으로 바꾼다.
- 선택 순서는 사용자가 고른 순서를 유지하지 않아도 되고, 태그 목록 순서를 따른다.
- `검색 초기화` 시 선택된 태그 필터도 모두 해제한다.
- 현재 검색 요약에는 선택된 태그명을 콤마로 표시한다.

## 상태 관리

- 검색 상태의 `tagId: string`을 `tagIds: string[]`로 바꾼다.
- 태그 삭제 시 검색 상태에 포함된 태그도 같이 제거한다.
- 활성 검색 여부 판단도 `tagIds.length > 0`으로 바꾼다.

## 테스트 전략

- API 테스트
  - 다중 태그가 모두 포함된 북마크만 반환하는지 확인
  - 검색어와 다중 태그 필터를 함께 썼을 때 AND 조건이 유지되는지 확인
- 웹 테스트
  - 체크박스 두 개를 선택하면 `tagId`가 반복된 쿼리 문자열로 요청하는지 확인
  - `검색 초기화` 시 모든 체크박스가 해제되는지 확인
