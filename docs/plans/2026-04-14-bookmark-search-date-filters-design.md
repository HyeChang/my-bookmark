# 북마크 기간형 검색 필터 설계

## 목표

- 북마크 목록 검색에 `최근 추가`와 `최근 열람` 기간 필터를 추가한다.
- 사용자는 각각 `전체 / 7일 / 30일` 중 하나를 선택할 수 있다.
- 기존 검색어, 검색 모드, 즐겨찾기/폴더/태그/색상/요약 필터, 정렬과 함께 조합해서 동작해야 한다.

## 접근 방식

### 옵션 1: 저장소 쿼리 레벨 필터

- `bookmarks` 저장소 쿼리 자체에 `createdWithin`과 `openedWithin`을 추가한다.
- 장점: 장기적으로 효율적이다.
- 단점: 현재 검색/정렬 로직이 저장소와 라우트에 분산되어 있어서 변경 범위가 커진다.

### 옵션 2: 라우트 후처리 필터

- 기존 저장소 조회 결과에 대해 라우트 레벨에서 기간 필터를 후처리한다.
- `createdWithin`은 `bookmark.createdAt` 기준으로 필터링한다.
- `openedWithin`은 `bookmark_activity` 집계 결과의 마지막 열람 시각 기준으로 필터링한다.
- 장점: 현재 구조에 최소 변경으로 추가할 수 있다.
- 단점: 결과를 메모리에서 한 번 더 거른다.

### 옵션 3: 별도 전용 검색 엔드포인트

- 고급 검색 전용 API를 따로 만든다.
- 장점: 확장성은 좋다.
- 단점: 지금 단계에서는 과하고, 기존 목록 로딩 코드가 분기된다.

## 추천안

- `옵션 2: 라우트 후처리 필터`로 간다.
- 현재 검색/정렬 슬라이스가 이미 라우트에서 `sort=opened_desc`를 후처리하고 있으므로, 기간 필터도 같은 층에서 처리하는 것이 가장 단순하다.

## API 설계

- 대상: `GET /api/bookmarks`
- 추가 쿼리 파라미터:
  - `createdWithin=7d|30d`
  - `openedWithin=7d|30d`
- 기본값은 둘 다 `all`로 취급한다.
- 유효하지 않은 값이 오면 `400 invalid_created_within` 또는 `400 invalid_opened_within`을 반환한다.

## 데이터 처리 규칙

- `createdWithin`
  - 현재 시각 기준으로 최근 `7일`, `30일` 이내에 생성된 북마크만 남긴다.
- `openedWithin`
  - `bookmark_activity`에서 사용자별 마지막 `open` 시각을 조회한다.
  - 마지막 열람 시각이 선택한 기간 이내인 북마크만 남긴다.
  - 한 번도 열람되지 않은 북마크는 `openedWithin` 필터에서 제외한다.
- 두 필터가 함께 들어오면 AND 조건으로 적용한다.

## UI 설계

- 북마크 검색 폼에 셀렉트 두 개를 추가한다.
  - `최근 추가`
  - `최근 열람`
- 옵션:
  - `전체`
  - `최근 7일`
  - `최근 30일`
- `검색 초기화` 시 두 필터는 모두 `전체`로 되돌린다.
- 현재 검색 요약 문구에도 선택된 기간 필터를 표시한다.

## 오류 처리

- 활동 저장소가 필요한데 사용할 수 없으면 `bookmark_activity_repository_unavailable`을 반환한다.
- 기간 필터가 없는 일반 목록 요청은 기존 동작을 그대로 유지한다.

## 테스트 전략

- API 테스트
  - `createdWithin=7d` 필터가 최근 생성 북마크만 남기는지 확인
  - `openedWithin=7d` 필터가 최근 열람 북마크만 남기는지 확인
  - 잘못된 기간 값이 400을 반환하는지 확인
- 웹 테스트
  - 두 셀렉트를 선택한 뒤 올바른 쿼리 문자열로 요청하는지 확인
  - `검색 초기화` 시 두 값이 `all`로 돌아가는지 확인
