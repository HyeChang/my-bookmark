# 폴더 트리 UI 정리 설계

## 목표

- 폴더 계층 구조가 화면에서 더 명확하게 보이도록 폴더 관리 영역을 트리 형태로 정리한다.
- 북마크 저장 폼, 검색 폼, 폴더 목록이 모두 같은 계층 순서를 공유하도록 맞춘다.
- 다음 슬라이스의 `같은 부모 안 드래그 정렬`을 붙이기 쉬운 UI 기반을 만든다.

## 범위

- 폴더 관리 목록을 계층 트리처럼 보이게 표현
- 하위 폴더의 들여쓰기/보조 텍스트 추가
- 폴더 셀렉트 순서를 트리 순서와 동일하게 유지
- 드래그 정렬, 접기/펼치기, 트리 커넥터 라인 등은 이번 범위에서 제외

## 접근 방식

### 추천안: 기존 계층 옵션 계산 로직 재사용

- 이미 있는 계층 옵션 계산 로직을 폴더 목록 렌더링에도 재사용한다.
- 각 폴더 행은 `이름`, `상위 폴더 보조 텍스트`, `수정/삭제 버튼`으로 구성한다.
- 하위 폴더는 들여쓰기와 `하위 폴더` 보조 문구로 구분한다.

장점:

- 저장 폼, 검색 필터, 폴더 목록의 순서를 한 곳에서 맞출 수 있다.
- 다음 단계에서 드래그 정렬 시 같은 트리 데이터 소스를 재사용하기 쉽다.
- 현재 테스트 범위를 최소 확장으로 가져갈 수 있다.

단점:

- 시각적으로는 정돈되지만, 아직 완전한 인터랙티브 트리는 아니다.

### 대안: 전용 트리 컴포넌트 분리

- 장기적으로는 맞지만, 지금은 컴포넌트 분리 비용이 더 크다.
- 이번 슬라이스는 트리 UI 정리만 목표라 과하다.

## UI 동작

- 상위 폴더는 일반 행으로 표시한다.
- 하위 폴더는 들여쓰기된 행으로 표시하고, `상위: <폴더명>` 보조 텍스트를 붙인다.
- 폴더 관리 목록에서도 저장/검색 셀렉트와 동일한 계층 순서를 유지한다.
- 폴더 이름 자체는 그대로 유지하고, 계층 표현은 보조 텍스트와 여백으로 드러낸다.

## 검증

- 폴더 트리 목록이 계층 순서대로 보이는지
- 하위 폴더에 `상위: ...`가 보이는지
- 저장 폼/검색 폼 옵션 순서가 트리 순서와 일치하는지

## 다음 단계

- 다음 슬라이스는 같은 부모 안 드래그 정렬
- 이번에 만든 계층 순서와 행 구조를 그대로 재사용해 드래그 핸들을 붙인다
