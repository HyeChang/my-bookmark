# 북마크 검색 UI 정리 및 태그 조건 전환 설계

## 목표

- 북마크 검색 UI를 `기본 검색`과 `고급 필터`로 분리해 현재보다 덜 길고 읽기 쉽게 만든다.
- 다중 태그 검색에 `모두 포함(AND)`과 `하나라도 포함(OR)` 전환을 추가한다.
- 현재 기본 동작은 유지해야 하므로 태그 조건 기본값은 `AND`로 둔다.

## 접근 방식

### 옵션 1: 현재 폼 유지 + 태그 조건 셀렉트만 추가

- 구현 범위는 가장 작다.
- 장점: 코드 변경이 적다.
- 단점: 검색 UI가 계속 길고, 필터가 많아질수록 사용성이 나빠진다.

### 옵션 2: 기본 검색/고급 필터 분리 + 태그 조건 전환

- 검색어, 검색 모드, 정렬, 실행/초기화는 기본 검색에 둔다.
- 나머지 필터는 `고급 필터` 영역으로 묶고 접기/펼치기 가능하게 한다.
- 장점: 지금까지 쌓인 필터를 유지하면서도 화면 부담을 줄일 수 있다.
- 단점: 상태가 하나 더 생긴다.

### 옵션 3: 별도 검색 모달 또는 사이드패널

- 검색 UI를 완전히 분리한다.
- 장점: 화면이 깔끔하다.
- 단점: 현재 단일 페이지 구조에서는 과하고, 구현 범위가 커진다.

## 추천안

- `옵션 2`로 간다.
- 현재 앱 구조를 크게 흔들지 않으면서도 검색 UI 정리 효과가 크다.
- 태그 조건 전환은 고급 필터 영역 안에 두는 것이 자연스럽다.

## UI 설계

### 기본 검색 영역

- `검색어`
- `검색 모드`
- `정렬`
- `검색 실행`
- `검색 초기화`
- `고급 필터 펼치기/접기`

### 고급 필터 영역

- `최근 추가`
- `최근 열람`
- `즐겨찾기만`
- `필터 폴더`
- `태그 조건`
  - `모두 포함`
  - `하나라도 포함`
- `필터 태그` 체크박스 목록
- `북마크 색상 필터`
- `URL 색상 필터`
- `요약 필터`

### 현재 검색 표시

- 긴 한 줄 문자열 대신 짧은 조건 칩 형태의 목록으로 바꾼다.
- 예:
  - `검색어: paper`
  - `정렬: 최근 열람순`
  - `태그 조건: 하나라도 포함`
  - `태그: research, video`

## 상태 설계

- `bookmarkSearchDraft`에 `tagMode: "and" | "or"` 추가
- 기본값은 `"and"`
- `isAdvancedSearchOpen` UI 상태 추가
  - 고급 필터에 값이 하나라도 있으면 기본적으로 열린 상태로 취급해도 된다.
- 태그 삭제 시 검색 상태의 `tagIds`에서도 제거한다.

## API 설계

- 대상: `GET /api/bookmarks`
- 추가 파라미터:
  - `tagMode=and|or`
- `tagIds`가 비어 있으면 `tagMode`는 무시한다.
- 기본값은 `and`

## 저장소 필터 규칙

- `and`
  - 선택한 모든 태그를 가진 북마크만 포함
- `or`
  - 선택한 태그 중 하나라도 가진 북마크를 포함

## 테스트 전략

### API

- `tagMode=or`일 때 하나만 포함해도 결과에 들어오는지 확인
- `tagMode=and` 기본값이 유지되는지 확인
- 잘못된 `tagMode`는 `400 invalid_tag_mode` 반환

### 웹

- `고급 필터` 토글이 열리고 닫히는지 확인
- `태그 조건`을 `or`로 바꾸면 쿼리에 `tagMode=or`가 들어가는지 확인
- 현재 검색 조건 표시가 칩 형태로 렌더되는지 확인
- `검색 초기화` 시 태그 조건도 `and`로 돌아가는지 확인
