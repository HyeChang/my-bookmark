# 원클릭 로컬 실행 런처 설계

## 목표

Windows에서 프로젝트 폴더 안의 실행 파일을 더블클릭하면, 로컬 테스트에 필요한 웹 빌드와 Worker 개발 서버 실행, 브라우저 열기를 한 번에 처리한다.

## 접근 방식

### 선택안

1. `cmd + PowerShell` 조합
   - 장점: Windows 더블클릭 진입점으로 가장 자연스럽고, PowerShell에서 오류 처리와 브라우저 열기를 다루기 쉽다.
   - 단점: 실행 정책 이슈를 고려해야 한다.

2. `cmd + node` 조합
   - 장점: 테스트하기 쉽다.
   - 단점: 브라우저 열기와 장기 실행 프로세스 관리가 Windows 쉘 문맥에서 덜 직관적이다.

3. `단일 .bat`
   - 장점: 파일 수가 적다.
   - 단점: 오류 처리와 사용자 메시지가 거칠고 유지보수가 불편하다.

### 결정

`cmd + PowerShell` 조합으로 간다.

- `start-bookmark-local.cmd`
  - 사용자가 더블클릭하는 진입점
  - PowerShell 스크립트를 호출한다.
- `scripts/start-bookmark-local.ps1`
  - 실제 실행 로직 담당
  - 루트 경로 이동
  - `npm run build:web`
  - 성공 시 브라우저 열기 예약
  - `npm run dev:api`
  - 실패 시 창을 닫지 않고 오류를 보여준다.

## 동작 흐름

1. 사용자가 `start-bookmark-local.cmd`를 더블클릭한다.
2. `.cmd`가 프로젝트 루트 기준으로 PowerShell 스크립트를 실행한다.
3. PowerShell 스크립트가 `npm run build:web`를 먼저 실행한다.
4. 빌드가 성공하면 짧은 지연 후 기본 브라우저로 `http://localhost:8787`를 연다.
5. 같은 창에서 `npm run dev:api`를 실행한다.
6. 서버 실행 중에는 창을 유지한다.
7. 빌드나 서버 실행이 실패하면 오류 메시지와 재시도 안내를 출력한다.

## 예외 처리

- `node` 또는 `npm`이 PATH에 없으면 즉시 실패 메시지를 보여준다.
- `build:web` 실패 시 `dev:api`는 실행하지 않는다.
- PowerShell 스크립트 경로를 찾지 못하면 `.cmd`에서 즉시 종료하지 않고 안내를 출력한다.
- 브라우저 열기는 실패해도 개발 서버 실행은 계속 진행한다.

## 테스트 전략

- Node 내장 테스트로 런처 구성값과 경로 계산 로직을 먼저 고정한다.
- PowerShell 스크립트는 작은 helper 모듈의 출력에 기대어 작성해, 핵심 판단 로직을 테스트 가능하게 둔다.
- 수동 검증은 다음 순서로 본다.
  - 런처 더블클릭
  - `build:web` 성공
  - 브라우저 자동 열림
  - `dev:api` 실행 유지
  - 실패 시 창이 닫히지 않고 오류 출력
