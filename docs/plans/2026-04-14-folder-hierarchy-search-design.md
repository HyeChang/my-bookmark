# 폴더 계층 검색 설계

## 목표

- 폴더 생성/수정 시 부모 폴더를 지정할 수 있게 한다.
- 북마크 검색 시 선택한 폴더뿐 아니라 하위 폴더까지 포함해 검색할 수 있게 한다.
- 폴더 계층을 만들 수 없는 상태에서 계층 검색만 제공하는 반쪽 기능을 피한다.

## 사용자 흐름

### 폴더 생성/수정

- 폴더 관리 폼에 `부모 폴더` 셀렉트를 추가한다.
- 기본값은 `상위 없음`이다.
- 사용자가 부모 폴더를 고르면 해당 폴더는 하위 폴더가 된다.
- 수정 시에는 자기 자신을 부모로 고를 수 없고, 자기 하위 폴더를 부모로 되돌리는 순환도 막는다.

### 북마크 검색

- 검색 필터의 `필터 폴더` 옆에 `하위 폴더 포함` 체크박스를 추가한다.
- 체크하지 않으면 기존처럼 선택한 폴더만 검색한다.
- 체크하면 선택한 폴더와 그 하위 폴더 전체를 포함해 검색한다.

## 접근 방식

### 추천안: 부모 지정 + 체크박스 기반 하위 폴더 검색

- 폴더 구조는 기존 `parentFolderId` 모델을 그대로 사용한다.
- 검색은 `folderId`와 `includeDescendantFolders=1` 조합으로 제어한다.
- API는 사용자 폴더 목록에서 하위 폴더 ID 집합을 계산한 뒤 북마크 검색 필터에 넘긴다.

장점:

- 현재 데이터 모델을 그대로 재사용할 수 있다.
- 기존 검색 동작을 깨지 않고 확장할 수 있다.
- 사용자가 원할 때만 하위 폴더를 포함해 더 안전하다.

단점:

- 라우트에서 폴더 트리 계산이 한 번 더 필요하다.
- 폴더 목록과 검색 UI 모두 계층 표현을 정리해야 한다.

### 대안 1: 폴더 선택 시 항상 하위 폴더 포함

- 구현은 단순하지만, 기존 `선택 폴더만` 검색과 의미가 달라진다.
- 사용자가 결과가 넓어지는 이유를 이해하기 어렵다.

### 대안 2: 계층 검색 없이 부모 지정만 먼저 도입

- 폴더 구조는 만들 수 있지만, 검색 요구사항이 남는다.
- 이번 목표를 절반만 해결하는 방식이라 제외한다.

## 데이터 및 API

### 폴더 CRUD

- `CreateFolderRequest`, `UpdateFolderRequest`의 `parentFolderId`를 실제 UI에서 사용한다.
- 폴더 생성 시 부모 폴더가 있으면 같은 사용자 소유인지 검증한다.
- 폴더 수정 시 아래 조건을 400으로 막는다.
  - 자기 자신을 부모로 지정
  - 자신의 자손 폴더를 부모로 지정
  - 존재하지 않거나 타인 소유인 부모 폴더 지정

### 북마크 검색

- `GET /api/bookmarks`에 `includeDescendantFolders=1`를 추가한다.
- `folderId`가 없으면 이 옵션은 무시한다.
- `includeDescendantFolders=1`이면 폴더 저장소에서 사용자 폴더 목록을 읽고, 대상 폴더의 자손 ID 집합을 계산한다.
- 북마크 저장소 필터에는 `folderId` 대신 `folderIds[]`를 넘겨 선택 폴더 또는 하위 폴더 포함 검색을 처리한다.

## UI

### 폴더 관리

- 폴더 관리 폼에 `부모 폴더` 셀렉트를 추가한다.
- 옵션 목록은 계층형으로 정렬하고 깊이에 따라 접두어를 붙인다.
- 편집 중인 폴더는 자신의 셀렉트 목록에서 제외한다.

### 검색 필터

- `필터 폴더` 선택 아래에 `하위 폴더 포함` 체크박스를 추가한다.
- 체크박스는 폴더를 선택한 경우에만 의미가 있다.
- 검색 요약 칩에도 `하위 폴더 포함`이 표시된다.

## 검증

### API 테스트

- 부모 폴더 지정 생성/수정
- 자기 자신 부모 지정 거부
- 자손을 부모로 지정하는 순환 거부
- `folderId + includeDescendantFolders=1` 검색 시 하위 폴더 북마크 포함

### 웹 테스트

- 부모 폴더 셀렉트 표시와 저장
- 검색 체크박스 표시와 요청 파라미터 반영
- 계층형 폴더 옵션 표시

## 범위 제외

- 폴더 트리 접기/펼치기 UI
- 드래그 정렬
- 다중 폴더 선택 검색
